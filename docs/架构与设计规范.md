## 二、路由清单

| 路径 | 页面 | 内容来源 | title 模板 |

| `*` | 404 | — | 页面未找到 · 低空原理实验室 |

**路由关系图**

```
/                      首页
 ├─ /principles        目录（章节卡片列表）
 │   └─ /principles/:chapterId   章节（知识点 + 本章实验）
 │       ├─ /points/:pointId     知识点（讲解 + 公式 + 考法）
 │       │   └─ /labs/:slug      关联实验
 │       └─ /labs/:slug
 ├─ /labs              实验室列表（按章分组）
 │   └─ /labs/:slug    实验室（预测→揭晓→归因→速查卡）
 └─ /about
```

**层级控制**：知识页 → 实验页 是唯一允许的"跨层跳转"，用侧栏卡片引导。其余一律向上一级。

## 四、核心交互机制：预测 → 揭晓 → 归因

这是本站与"调参数看变化"类科普站的根本差别，也是社媒分享的来源。

| 步骤 | 组件状态 | 用户看到 | 可分享物 |
|---|---|---|---|
| 1 · 先猜 | 4 个选项，未揭晓 | "猜错才是这里的目的" | — |
| 2 · 揭晓 | 正确项绿、错选红、其余降透明 | 归因说明（Markdown + 公式） | — |
| 3 · 落到实操 | 橙色提示框 | "这在你手上是哪根杆" | 错题截图 |
| 4 · 带走 | 速查卡 | 可打印 A4 / 一键复制 | 速查卡图片 |

**为什么这样设计**：用户分享的不是"我看了个科普"（无传播力），而是"我猜错了"（有话题性）。
速查卡是可打印物，适合放进学员的复习文件夹——这是留存钩子。

## 五、性能预算与实测

| 项 | 预算 | 实测 |
|---|---|---|
| 首屏 JS（gzip） | < 120KB | 97KB（不含懒加载的 KaTeX） |
| 首屏 CSS（gzip） | < 20KB | 5.6KB（KaTeX CSS 已分离） |
| 首屏 HTML（gzip） | < 5KB | ~1.3KB |
| 字体总量 | < 400KB | 292KB（已裁剪 40 个冗余文件） |
| 字体请求数 | < 25 | 19（仅 woff2） |
| 整体 dist | < 1.5MB | 948KB |

**优化手段**

1. KaTeX 引擎动态 `import()`，只在内容含公式时加载（77KB gzip 独立 chunk）
2. KaTeX CSS 分离到独立 chunk（首页不加载）
3. 构建后裁剪 ttf/woff 冗余字体，只留 woff2
4. `vendor-react` / `vendor-katex` / `vendor-marked` 手动分包
5. `marked` 同步渲染无公式内容，零额外等待
6. 全部 SVG 内联，无图片请求
7. 无外部字体 / 无外部 CDN 依赖

## 七、部署配置

### EdgeOne Pages（推荐，主站）

| 项 | 值 |
|---|---|
| 项目类型 | 导入 Git 仓库（GitHub） |

| 回退规则 | 匹配 `(.*)`（排除静态资源）→ 重写 `/index.html` |
| HTTPS | 申请免费证书 → 开启强制 HTTPS |

### Cloudflare Pages（备份线路）

| 项 | 值 |
|---|---|
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| 回退 | `public/_redirects` 已内置 `/* /index.html 200` |

### DNS 方案

```
nbyteair.com          NS → Cloudflare   （官网继续用，不动）
  └ www.nbyteair.com  CNAME → CF Pages   （官网）
  └ lab.nbyteair.com  NS → DNSPod        （实验室，境内解析）
                          └ CNAME → EdgeOne 分配地址
```

**要点**

- CF 托管的裸域名不支持 CNAME 接入 → 必须用子域，正好符合规划
- CF 橙云代理必须关闭（灰云），否则 CNAME 指向失效
- 实验室用 EdgeOne 大陆可用区需域名已完成 ICP 备案（阿里云接入）
