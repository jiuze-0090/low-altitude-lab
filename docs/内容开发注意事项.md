## 一、先记住三条铁律

1. **内容只写进 `src/content/` 下的数据文件**，不要在组件里硬编码文案。
   站点已接入构建期静态预渲染：构建时自动读取内容数据，为每个页面生成一份带完整正文的静态 HTML，供 Google / 百度 / AI 爬虫在无 JS 环境下抓取。内容写错地方 = 爬虫读不到。
2. **加完内容必须重新 `npm run build` 并重新部署**。
   静态页是构建产物。只改数据不重新构建部署，线上不会变。
3. **新增内容不要改 `vite/plugins/prerender.ts`**。
   插件从 `sitemapUrls()` 自动取页面清单、从内容数据自动取正文。只要按本文的字段规范写，新页面会自动被预渲染。

| 要改什么 | 文件 | 数据结构 |

| 新增/改实验 | `src/content/experiments/e<N>-<slug>.ts` 或 `m<N>-<slug>.ts` | `Experiment` |

| 站点名/热线/公众号 | `src/content/index.ts` 的 `siteMeta` | `SiteMeta` |

| 类型定义（别改） | `src/types/content.ts` | — |

**新增一个知识点/实验的完整动作 = 三步**：
1. 在对应数据文件里加对象；
2. 在 `index.ts` 顶部 import，并加进 `knowledgePoints` 或 `experiments` 数组；
3. （实验还要）把 `id` 挂到所属 `chapter` 的 `experimentIds`，知识点挂到 `knowledgePointIds` / 实验的 `knowledgePointIds`。

漏了第 2 步，页面和静态页都不会出现。

## 三、SEO / GEO 必填字段（直接决定静态页质量）

预渲染插件会把下面这些字段写进静态 HTML 的 `<title>`、`<meta description>` 和正文。**空着或写得含糊，这一页在搜索和 AI 里就是废页。**

### 知识点（KnowledgePoint）

| 字段 | 用途 | 要求 |
|---|---|---|
| `id` | URL（`/points/<id>`） | 英文短横线，`kp-` 开头，全站唯一，**定了别改**（改了旧链接失效） |
| `title` | H1 + `<title>` 前半段 | 具体，带关键词。例：`升力方程：三个量决定升力`，别写「知识点一」 |
| `summary` | `<meta description>` + 开头速览 | 1~2 句，**结论前置**，含关键数字/关系。这是 AI 最爱引用的段落 |
| `body` | 正文主体（Markdown） | 详细讲解，支持 `$$公式$$` 和表格；必须先给结论再展开 |
| `formulas` | 「核心公式」区块 | 字符串数组，KaTeX 语法（不带 `$$`） |
| `examAngles` | 「高频考法」列表 | 带真实题号，例：`...（题号 338）` |
| `onYourStick` | 「这在你手上是哪根杆」 | 把原理落回学员操作动作，本站特色，务必写 |
| `chapterId` | 归属章节 + 面包屑 | 必须是 `chapters` 里已有的 id |

### 实验（Experiment）

| 字段 | 用途 | 要求 |
|---|---|---|
| `slug` | URL（`/labs/<slug>`） | 英文短横线，**定了别改** |
| `title` | H1 + `<title>` | 口语化提问式更好，例：`升力到底从哪来` |
| `hook` | `<meta description>` + 页面钩子 | 一句话勾住读者 |
| `quickTake.conclusion` | 「30 秒速览」结论 | **先给结论**，AI 引用高发区 |
| `quickTake.points` | 速览要点 | 2~3 条 |
| `prediction.prompt` | 「先猜一次」题干 | 选择题题干 |
| `prediction.attribution` | 「揭晓与归因」正文（Markdown） | 讲清因果，不是只给答案 |
| `principle` | 「原理详解」正文（Markdown） | 支持公式与表格 |
| `cheatsheet.rows` | 速查卡表格 | `{term, value, note}` |
| `examRefs` | 「这在考试里怎么问」 | `{code, gist}`，带真实题号 |
| `fieldNotes` / `fieldNote` | 实飞经验 | 教员口吻 |
| `chapterId` / `knowledgePointIds` | 归属与关联 | 用已有 id |

## 四、Markdown 与公式写法

- 正文用 `String.raw\`...\`` 包裹，**保留 LaTeX 反斜杠**（普通模板字符串会把 `\t`、`\r` 等转义吃掉）。
- 独立公式：`$$...$$`；行内公式：`$...$`。
- 公式要能被 KaTeX 识别： `\tfrac{1}{2}\rho V^2` 这类写法可以；自定义的 `\text{中文}` 可能报错，慎用。
- 表格用标准 Markdown 管道语法，预渲染会转成 HTML `<table>`。
- `℃` 这类符号在 KaTeX 公式里会警告（构建时显示 `No character metrics for '℃'`），正文里用没问题，别放进 `$...$` 里。
- **中文引号用 `“”`，不要用直引号 `"`**。marked 会把直引号转成 HTML 实体 `&quot;`，
  浏览器和百度会正常解码，但纯文本提取工具（部分 AI 爬虫）可能读到字面量 `&quot;`。
  中文正文用 `“”` 既符合排版规范，也彻底避开这个问题。

示例（照抄结构）：

```ts
body: String.raw`
### 升力由三个量决定

$$L = C_L \cdot q \cdot S$$

| 符号 | 含义 | 变不变 |
|---|---|---|
| $C_L$ | 升力系数 | 由迎角决定 |

**速度减半，升力只剩四分之一。**
`
```

## 五、新增内容后的验收清单

改完数据，**在本地跑一遍**：

```bash
cd D:/wbspace/网站--新字节航空/low-altitude-lab
npm run build
```

构建日志出现这一行就说明静态页生成了：

```
[plugin prerender] prerender：已生成 52 个静态页（含完整正文 + 独立 head + JSON-LD）
```

（数字随内容增长变大。当前基线：52 个静态页 = sitemap 52 条 URL。新增 1 个知识点 = 从 52 变 53。）

**验收 5 项**（在 `dist/` 里查）：

1. `dist/sitemap.xml` 里有新页面 URL；
2. `dist/points/<新id>/index.html` 或 `dist/labs/<新slug>/index.html` 存在；
3. 打开该 HTML，能看到 `<title>` 是新标题、`<link rel="canonical">` 是本站绝对地址；
4. 页面正文里能看到 `summary` / `body` 的中文（不是空壳 `<div id="root"></div>`）；
5. **公式页额外查**：正文里不应出现 TeX 源码（`\cdot`、`\tfrac`、`\qquad`），
   也不应出现 `katex-mathml`。出现即说明公式被渲染了多份，AI 爬虫会把同一公式读三遍。

typecheck 必过：`npm run typecheck`。

## 六、不要做的事

| 别做 | 原因 |
|---|---|
| 改 `id` / `slug` | 旧 URL 立刻失效，搜索引擎和学员收藏的链接全断 |
| 在组件里写死文案 | 预渲染读不到，爬虫看到空壳 |
| 只改数据不 build / 不部署 | 线上不变 |
| 把 `summary` 写成「本节介绍...」 | 浪费 AI 引用位，要写结论和数字 |
| 用 `dangerouslySetInnerHTML` 塞外部 HTML | 安全与 SSR 风险，内容走 Markdown |
| 手动改 `dist/` 里的文件 | 下次 build 全被覆盖 |
| 内容里写未经题库核对的题号 | 站点定位是「题库实测」，题号错了信誉受损 |
| 改 `vite/plugins/prerender-lib.ts` 里的 KaTeX `output` | 必须保持 `'html'`（与客户端 `Markdown.tsx` 一致）。改成 `'htmlAndMathml'` 会多输出 MathML + `<annotation>` 里的 TeX 源码，爬虫纯文本提取时同一公式被读三遍 |

## 七、部署说明（发布的人看）

`dist/` 是整个静态产物根目录，直接部署到 EdgeOne Pages（`edgeone.json` 已配好 SPA fallback）。

- EdgeOne 的 `/* → /index.html` 是 **SPA fallback**：静态文件优先，只有没匹配到任何静态资源/路由时才回退到首页。所以 `dist/points/<id>/index.html` 这类静态页能被直接访问到，不会被回退吃掉。
- 部署后抽验：`curl -s https://lab.nbyteair.com/points/<新id> | grep -o '<title>[^<]*</title>'`，应返回该页自己的标题，而不是「低空原理实验室」。
- 每次内容更新后：build → 部署 → 抽验，三步缺一不可。

## 八、背景：为什么要这么麻烦

站点是 React SPA，真人访问时 JS 会渲染完整页面。但 Googlebot 之外的搜索引擎、以及 GPTBot / ClaudeBot / PerplexityBot 等 AI 爬虫**大多不执行 JS**，它们直接看服务器返回的原始 HTML。改造前原始 HTML 只有 `<div id="root"></div>` 空壳，52 个 URL 返回同一份，AI 完全读不到内容。

构建期预渲染解决的就是这个：构建时把内容数据渲染成带全文的静态 HTML，React 挂载后自动接管（真人无感），爬虫/AI 则读到完整正文 + 独立 title + canonical + Article/BreadcrumbList 结构化数据。

**所以内容开发的产出质量（尤其 title / summary / body）直接决定 GEO 效果。**
